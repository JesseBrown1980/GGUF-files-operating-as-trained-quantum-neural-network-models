# Does the 6,561-head shared GGUF model know anything?

**Test date:** 2026-11-13. This is a genuine *inference* test, not lossless compression of an existing known byte stream. The [question set and answers](KNOWLEDGE-PROBE-PREDICTION.hbp) were frozen before the test program existed. The [measured HBP](KNOWLEDGE-PROBE-MEASURED.hbp) and [hosted run](https://github.com/JesseBrown1980/GGUF-files-operating-as-trained-quantum-neural-network-models/actions/runs/43361650290) preserve the actual generated bytes and negative results.

## What model was questioned

The test loads and SHA-256 checks the **same** [full 6,561-head synthetic GGUF checkpoint](FULL6561-MEASURED.hbp) as PR #26:

`606c4d8478b8dbd72dfda0dad6c6ef1895c081a7cd5d5bb6c363525f57b941b2`

Its architecture is intentionally small: **one 256×256 byte-bigram conditional predictor** with one set of **three signed class-logit corrections per parent and leaf**. An 81×81 router uses the preceding bytes to select corrections. It is a real trained *statistical byte model* but **not** a transformer/LLM; the training source is synthetic character streams, not the original 6,561 operator files or factual documents.

## The direct factual test

Eight questions cover geography, arithmetic, relativity, chemistry and general facts. Every question is posed in two ways (short and more-than-256-byte framing), with three model configurations (static shared base, parent router and full 6,561-head tree). All arms generate their own **new** 64-byte responses, not reconstruct supplied answers. No search, external assistant or symbolic engine answers the questions. Greedy output is scored using exact case-insensitive first-answer matching with a word boundary, and seeded integer sampling is also archived.

**Measured result: 0/48 correctly answered prompts.** For each combination of routing mode and short/long context, all eight different questions yielded *one identical greedy continuation*. On short questions the full tree produced `A0111111111...`, while the longer framing produced tabs. Sampling yielded nonsemantic random character, digit and punctuation streams.

The failure is architectural, not a surprise: the conditional-byte predictor sees **one prior byte**, and the routed class bias sees at most the recent byte-family statistics. It cannot retrieve concepts, named entities, factual relationships or compute an answer from a question. France and Japan prompts ending with `Answer: ` have the same last byte; in the shared base model they necessarily have identical conditional distributions for their first generated byte. The hosted test checked and preserved their identical full greedy completions.

## What it *does* discriminate: synthetic style

After the zero-score QA result, a separate **post hoc**, non-blind check was introduced and [marked as such](KNOWLEDGE-PROBE-POSTCHECK.hbp). It asks whether the trained router distinguishes *the three synthetic source style families* established by the fixture generator: letter-heavy, digit-heavy and newline-heavy. This is not JSON/Python/Wikipedia classification.

| Test | Parent router | Full tree |
|---|---:|---:|
| Correct three-way synthetic family after 256 bytes | **6,561/6,561** | **6,561/6,561** |
| Exact parent ID after 256 bytes | 422/6,561 | 422/6,561 |
| Exact specialist leaf ID after all 512 bytes | 4/6,561 (parent-only representative ID) | **6/6,561** |
| Distinct parent addresses selected | 8 | 8 |

The fixed-family baseline is 2,187/6,561, or 33.3%. The observed 100% **is restricted to the intentionally distinct synthetic generator classes**. It is not evidence of semantic understanding, unsupervised identification of 6,561 independent documents, or real-file type recognition. Most leaf heads were not identified reliably.

## Reproduction

```sh
# Regenerate the checkpoint from the exact frozen synthetic generator:
cargo +1.81.0 run --release --locked --bin shared_6561 -- --fixture-6561 build/knowledge/fixture

# Generate and score 8 questions x 2 contexts x 3 modes:
cargo +1.81.0 run --release --locked --bin shared_knowledge_probe -- --probe \
  build/knowledge/fixture/full_tree.gguf build/knowledge/probe

# Exploratory 3-way synthetic-family recognition:
cargo +1.81.0 run --release --locked --bin shared_knowledge_probe -- --style \
  build/knowledge/fixture/full_tree.gguf \
  build/knowledge/fixture/target.raw build/knowledge/probe
```

The [hosted workflow](../.github/workflows/knowledge-probe.yml) checks the exact model hash, Rust 1.81 format/clippy, frozen questions, scores, and same-suffix controls. Download its `real-gguf-6561-factual-knowledge-probe` artifact for `KNOWLEDGE-RESULT.hbp`, `STYLE-RESULT.hbp`, and all raw 64-byte greedy completions.

## Scientific next step

This architecture is useful for **routing and byte-distribution adaptation** but is too restricted to use as a source of factual knowledge. Better tests must use real, independently held-out text and code, a longer-context trained predictor, or explicit source-backed retrieval plus a deterministic answer engine. A 6,561-address hierarchy does not itself confer understanding or learned memories. Compare against a generalist on the *same actual input* and retain all cost accounting and failed controls. Real operator-file training remains NOT RUN in the GitHub-hosted fixture.
